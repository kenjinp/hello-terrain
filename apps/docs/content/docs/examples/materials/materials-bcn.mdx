This example renders the terrain texturing API, not detached material spheres. Four slots—rocky ground, cliff, moss, and forest stone—share the phase-one fast packing. Switch flat/cube-sphere projection, control-field array/atlas capacity, one/four corners, height blending, and LOD focus using the scene controls. The HUD reports actual array layers, mip count, compression, and field backend.

## Two packed arrays

| Asset | Channels | Native GPU format | Dimensions | Layers | Mips | File bytes |
|---|---|---|---|---|---|---|
| `albedo-height.ktx2` | RGB albedo, A height | `bc3-rgba-unorm-srgb` | 512×512 | 4 | 10 | 1,398,656 |
| `normal-ao-roughness.ktx2` | RG normal XY, B AO, A roughness | `bc3-rgba-unorm` | 512×512 | 4 | 10 | 1,398,656 |

Files live under `/assets/materials/terrain-fast/`. Alpha carries material data, not transparency. Albedo RGB is sRGB; height alpha and the entire second array remain linear. Normal Z is reconstructed from XY. Both files include the complete 512-to-1 mip chain; their listed download sizes include KTX2 headers and are not a memory/performance benchmark.

These are **native BC3 KTX2 assets**, not Basis Universal payloads. The example requires WebGPU's `texture-compression-bc` feature and reports an explicit unsupported-device error if absent. It does not claim universal device support or silently replace compressed materials with an unrelated fallback.

## Loading and ownership

The example loader validates the KTX2 header, layers, and per-level byte lengths. In three.js r186, the native KTX2 path does not construct an array texture from `layerCount`, so the loader explicitly constructs `CompressedArrayTexture` from the loaded mip payloads. Passing the loader's ordinary `CompressedTexture` directly to the terrain API is not sufficient.

Once the two matching arrays are loaded, the public binding is:

```ts
import { terrainTextureSetFromArrays } from "@hello-terrain/three";

const textureSet = terrainTextureSetFromArrays(
  { albedoHeight, normalRoughAo },
  [
    { name: "Rocky ground", uvScale: 14, antiTiling: "detile" },
    { name: "Cliff", uvScale: 20, projection: "vertical" },
    { name: "Moss", uvScale: 12, antiTiling: "detile" },
    { name: "Forest stone", uvScale: 16 },
  ],
);
// Supply textureSet with a texture callback to useTerrain or the core graph.
// After every consumer has detached:
textureSet.dispose();
```

The set takes ownership of these arrays, keeps their compressed mip data, and disposes them idempotently. The React scene releases its owned assets on unmount. Runtime packing from ordinary loaded maps is a separate path; see [Terrain Texturing](/docs/core/nodes/texturing).

## What was checked

On Apple/Metal WebGPU with three.js 0.186.1, all four layers and all ten mip levels of both arrays were sampled and compared with an independent CPU BC3 decode. The actual GPU formats were the two formats listed above. The terrain scene also exercised the atlas backend, cube-sphere, moving LOD, and both corner counts. This demonstrates decoded content and working bindings on that device, not throughput, cross-vendor quality, or seamless cube-face material mapping.
