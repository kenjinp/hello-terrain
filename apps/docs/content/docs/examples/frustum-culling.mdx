## Overview

These examples render terrain from the main viewer camera while a second animated camera drives quadtree visibility. The yellow camera helper marks the culling frustum; the visible wireframe terrain is the set of tiles inside that frustum.

With `@hello-terrain/react`, pass the culling camera through `useTerrain({ camera })` or `<Terrain camera={...} />`. The runner calls `writeUpdateParamsFromCamera` each frame using that camera's view-projection matrix.

```tsx
const terrain = useTerrain({
  rootSize: 180,
  maxLevel: 10,
  elevation,
  camera: cullingCamera,
});

<Terrain terrain={terrain}>
  {({ positionNode }) => (
    <meshStandardNodeMaterial positionNode={positionNode} wireframe />
  )}
</Terrain>
```

Animate and update the culling camera before the terrain runner reads it each frame (`lookAt`, `updateProjectionMatrix`, and so on).

For low-level graph setups, you can still call `writeUpdateParamsFromCamera` directly inside a custom `graph.set(quadtreeUpdate, ...)` callback.

## Cube-sphere

A closed planet built with `createCubeSphereTopology`. The culling camera orbits at planet scale while the viewer can pull back to see the whole sphere.

Cube-sphere terrain also applies **horizon culling**: tiles fully behind the planet are removed even when they would still intersect the view frustum. That is expected — the far side of the sphere should not stay resident when viewed from outside.

```tsx
const topology = createCubeSphereTopology({ radius: 1000 });

const terrain = useTerrain({
  topology,
  radius: 1000,
  maxLevel: 10,
  elevation,
  camera: cullingCamera,
});
```

## Torus

A closed donut built with `createTorusTopology`. Both surface axes wrap, so frustum bounds come from the torus topology hooks while the same second-camera pattern drives visible tiles.

```tsx
const topology = createTorusTopology({
  majorRadius: 1000,
  minorRadius: 360,
});

const terrain = useTerrain({
  topology,
  maxLevel: 10,
  elevation,
  camera: cullingCamera,
});
```
