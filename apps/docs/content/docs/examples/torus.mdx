## Overview

This example demonstrates `createTorusTopology`, a closed donut surface that is periodic in **both** axes. It exists primarily as a stress test of the topology + projection abstraction: adding a brand-new surface shape requires no changes to the GPU pipeline, the CPU query/raycast machinery, or the React runtime. Each surface injects a `SurfaceProjection` strategy, and the rest of the system never branches on a projection kind.

The torus parametrizes its surface by `(u, v)` in `[0, 1)`:

- `u` sweeps around the **major circle** (the ring of the donut), and
- `v` sweeps around the **tube cross-section**.

Both axes wrap, so every tile has a same-level neighbor (modulo the level resolution) and there is a single root tile that covers the whole donut.

### How it works

- **One periodic space** — `rootTiles` emits a single level-0 root. `neighborSameLevel` wraps `x`/`y` modulo `2^level` on both axes, so the surface is seamless all the way around.
- **Injected projection** — `createTorusProjection` supplies the GPU vertex/normal builders (torus position + outward normal) and the CPU surface math (position → `(u, v)`, displaced position, cross-product normal, camera offset, and a signed-distance raycast). The same `SurfaceProjection` interface backs the flat and cube-sphere surfaces.
- **Conservative bounds** — `tileBounds` samples a 3×3 grid across each tile (corners alone collapse for tiles that span a full circle), producing a stable camera-relative bounding sphere for LOD.
- **Seamless elevation** — the elevation function receives the torus `worldPosition`. Sampling 3D noise in world space keeps terrain continuous across both wrap seams without any UV-seam handling.

### Same runtime, different surface

The interactive marker and click-to-pick behavior use the **generic** closed-surface runtime — identical to the cube-sphere example:

```ts
// Project any world point onto the surface and read the sample back.
const sample = terrain.runtime.surfaceQuery?.sampleTerrainByPosition(point);

// CPU ray pick against the displaced surface.
const hit = terrain.runtime.raycast?.pick(ray);
```

`surfaceQuery` is exposed for every closed surface (cube-sphere and torus); the cube-sphere additionally exposes `sphereQuery` with direction/lat-long keys. Flat surfaces expose neither — they use the XZ-keyed `query`.

### Controls

| Control | Description |
|:--|:--|
| **major radius** | Distance from the donut center to the tube center |
| **minor radius** | Radius of the tube cross-section |
| **max level** | Maximum quadtree subdivision depth |
| **max nodes** | Total node budget |
| **elevation scale** | Displacement applied along the surface normal |
| **skirt scale** | Skirt drop distance (inward) to hide tile seams |
| **noise frequency** | Spatial frequency of the 3D terrain noise |
| **sea level** | Threshold below which terrain is flattened into ocean |
| **marker angle** | Angle (around the ring) of the surface-query marker |
| **wireframe** | Toggle wireframe to visualize the tiling |
