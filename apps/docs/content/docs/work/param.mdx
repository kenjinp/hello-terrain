---
title: Param
description: Reactive parameters for the task graph
---

A `Param` is a small reactive container you can:
- read (`get()`)
- update (`set(valueOrCb)`)
- reset (`reset()`)
- observe (`subscribe(cb)`)

Params are usually the **inputs** to tasks. When a param changes, dependent tasks become **dirty** and will recompute on the next `g.run()`.

## Creating a Param

```ts
import { param } from "@hello-terrain/work";

const count = param(0);
const name = param("hello");
const config = param({ debug: true, maxRetries: 3 });
```

`param(initial)` infers the type from the initial value and returns a `ParamRef<T>`.

## API Reference

### param(initial)

Creates a new reactive parameter.

| Parameter | Type | Description |
|-----------|------|-------------|
| `initial` | `T` | The initial value of the parameter |

**Returns:** `ParamRef<T>`

## ParamRef Interface

### get()

Returns the current value of the parameter.

```ts
const width = param(100);
console.log(width.get()); // 100
```

### set(valueOrCallback)

Updates the parameter value using either a direct value or a callback function. The callback receives the previous value and returns the new value.

```ts
const count = param(0);

// Direct replace
count.set(5);

// Increment from previous value
count.set((prev) => prev + 1);

// Replace entirely with callback
count.set(() => 42);

// Chain updates (fluent API)
count
  .set((prev) => prev + 1)
  .set((prev) => prev * 2);
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `valueOrCallback` | `T \| ((prev: T) => T)` | Direct value or updater callback |

**Returns:** `ParamRef<T>` (for chaining)

### reset()

Resets the parameter back to the original `initial` value passed to `param(initial)`.

```ts
const count = param(10);

count.set(42);
console.log(count.get()); // 42

count.reset();
console.log(count.get()); // 10
```

**Returns:** `ParamRef<T>` (for chaining)

### subscribe(callback)

Subscribes to value changes. The callback is invoked whenever the param is updated via `set()`.

```ts
const theme = param("light");

const unsubscribe = theme.subscribe((next, prev) => {
  console.log(`Theme changed from ${prev} to ${next}`);
});

theme.set("dark");
// Logs: "Theme changed from light to dark"

// Clean up when done
unsubscribe();
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `callback` | `(next: T, prev: T) => void` | Function called on each value change |

**Returns:** `() => void` - Unsubscribe function

### displayName(name)

Assigns a human-readable name for debugging and visualization.

```ts
const playerHealth = param(100).displayName("playerHealth");
console.log(playerHealth.name); // "playerHealth"
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `name` | `string` | Display name for the parameter |

**Returns:** `ParamRef<T>` (for chaining)

### Properties

| Property | Type | Description |
|----------|------|-------------|
| `kind` | `"param"` | Type discriminator for distinguishing params from tasks |
| `id` | `string` | Unique identifier (UUID) |
| `name` | `string \| undefined` | Display name if set |

## Examples

### Counter

```ts
const count = param(0).displayName("count");

// Read
console.log(count.get()); // 0

// Update
count.set((n) => n + 1);
console.log(count.get()); // 1

// Subscribe
count.subscribe((next, prev) => {
  console.log(`Count: ${prev} → ${next}`);
});

count.set((n) => n + 1); // Logs: "Count: 1 → 2"
```

### Configuration Object

```ts
interface Config {
  apiUrl: string;
  timeout: number;
  retries: number;
}

const config = param<Config>({
  apiUrl: "https://api.example.com",
  timeout: 5000,
  retries: 3,
}).displayName("config");

// Update a single field
config.set((prev) => ({
  ...prev,
  timeout: 10000,
}));

// Read current config
const current = config.get();
console.log(current.timeout); // 10000
```

### Using with Tasks

Params are the primary way to inject changing input values into a task graph:

```ts
import { param, task, graph } from "@hello-terrain/work";

const basePrice = param(100).displayName("basePrice");
const taxRate = param(0.08).displayName("taxRate");

const totalPrice = task((get, work) => {
  const base = get(basePrice);
  const tax = get(taxRate);
  return work(() => base * (1 + tax));
}).displayName("totalPrice");

const g = graph();
g.add(totalPrice);

await g.run();
console.log(g.get(totalPrice)); // 108

// Update input and re-run
taxRate.set(0.10);
await g.run();
console.log(g.get(totalPrice)); // 110
```

## Graph-Scoped Params

By default, a `param` holds a single shared value. When a task calls `get(param)`, it reads that
shared value and the graph subscribes to changes via `param.set()`.

For **multi-instance** use cases (e.g. two terrain meshes in the same scene), you need each graph
to have its own copy of a param's value. `graph.set()` does exactly this — it takes **graph-local
ownership** of a param, storing an isolated value that only that graph sees.

### Declaring params at module scope

```ts
// params.ts — shared declarations with sensible defaults
import { param } from "@hello-terrain/work";

export const rootSize = param(256);
export const maxLevel = param(16);
```

### Using `graph.set()` for per-instance values

```ts
import { graph, task } from "@hello-terrain/work";
import { rootSize, maxLevel } from "./params";

const configTask = task((get, work) => {
  const size = get(rootSize);
  const level = get(maxLevel);
  return work(() => ({ size, level }));
}).displayName("configTask");

// Graph 1 — own values
const g1 = graph()
  .add(configTask)
  .set(rootSize, 128)
  .set(maxLevel, 12)
  .reset(maxLevel);

// Graph 2 — different values, same param tokens
const g2 = graph()
  .add(configTask)
  .set(rootSize, 512)
  .set(maxLevel, 20)
  .reset();

await g1.run();
await g2.run();

console.log(g1.get(configTask)); // { size: 128, level: 12 }
console.log(g2.get(configTask)); // { size: 512, level: 20 }
```

### How ownership works

- Before `graph.set()` is called, the graph subscribes to `param.subscribe()` — exactly like today.
- The first `graph.set(param, valueOrCb)` call **detaches** the external subscription and stores a graph-local value.
- That graph-local value is seeded from `param.get()`, but plain objects and arrays are **deep-copied** so each graph owns its own copy and the shared default is never mutated. Functions, class instances, typed arrays, `Map`/`Set`, etc. are kept by reference.
- Subsequent `graph.set()` calls update the graph-local value and mark downstream tasks dirty.
- External `param.set()` calls no longer affect a graph that has taken ownership.
- `graph.reset(param)` resets one graph-owned param back to a fresh copy of its owned baseline.
- `graph.reset()` resets all graph-owned params in the graph.

### Object-valued params

Every graph gets its own copy of an object default, so two graphs can never see each other's
edits — even if the updater mutates `prev` in place:

```ts
const cameraConfig = param({ cameraOrigin: { x: 0, y: 0, z: 0 }, mode: "distance" });

const a = graph().set(cameraConfig, (prev) => ({ ...prev, cameraOrigin: { x: 1, y: 0, z: 0 } }));
const b = graph().set(cameraConfig, (prev) => ({ ...prev, cameraOrigin: { x: 2, y: 0, z: 0 } }));

// a → x: 1, b → x: 2, and the module-scope default is untouched:
cameraConfig.get().cameraOrigin.x; // 0
```

<Callout type="note">
  In-place mutation of `prev` (`prev.cameraOrigin.x = 1; return prev`) is safe per graph, but
  **immutable updates are still recommended**: returning a new object keeps intent obvious and
  means the value can be shared with other code without surprises.
</Callout>

<Callout type="warn">
  Only `graph.set()` copies. A task that merely calls `get(param)` on a graph that never bound that
  param reads the shared `param.get()` value directly — mutate it and every graph sees the change.
</Callout>

<Callout type="note">
  You can mix owned and unowned params in the same graph. Only params you explicitly
  `graph.set()` become graph-local; the rest continue to use the shared subscription flow.
</Callout>

<Callout type="note">
  `graph.reset()` is graph-local. It does not reset shared/global params that are only
  tracked through the normal `param.subscribe()` flow.
</Callout>

## Type Safety

Params are fully typed—the type is inferred from the initial value or can be explicitly specified:

```ts
// Type inferred as ParamRef<number>
const count = param(0);

// Explicit type annotation
const items = param<string[]>([]);

// Complex types
interface User {
  id: string;
  name: string;
}
const currentUser = param<User | null>(null);
```
