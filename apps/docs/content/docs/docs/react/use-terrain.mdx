---
title: useTerrain
description: Own and drive the shared terrain runtime from React
---

`useTerrain(options)` creates a stable runtime controller and applies data changes after commit. Recreating an options object does not recreate the runtime. The hook drives the same `createTerrain` implementation used by vanilla Three and releases its exact lifecycle generation on cleanup, including Strict Mode replay.

```tsx
const terrain = useTerrain({
  rootSize: 256,
  elevation,
  elevationRange: { min: -1, max: 1 },
  elevationScale: 20,
  maxNodes: 1024,
  innerTileSegments: 61,
});
return <Terrain terrain={terrain}>
  {({ positionNode, materialContext }) => (
    <meshStandardNodeMaterial positionNode={positionNode}
      colorNode={materialContext?.elevation.smoothstep(0, 20)} />
  )}
</Terrain>;
```

The handle exposes:

| Member            | Contract                                                                           |
| ----------------- | ---------------------------------------------------------------------------------- |
| `controller`      | Shared runtime: configuration, updates, queries, managed invalidation and disposal |
| `status`          | Subscribed render/query revisions, pending work, lifecycle and last error          |
| `binding`         | Scene transform/query binding while mounted; otherwise null                        |
| `positionNode`    | Published terrain position node, or null before publication                        |
| `materialContext` | Direct elevation, datum/base normals and source mapping nodes                      |

Configure through `terrain.controller.configure(patch)`. The hook owns frame driving and applies configuration after commit.

Topology is the geometry authority. `rootSize`/`origin` are conveniences for the default flat topology; explicit topologies supply their own dimensions. `lod`, `elevationRange`, `queries`, `maxNodes`, `maxLevel`, `innerTileSegments`, `skirtScale`, `elevationScale`, `elevation` and `terrainFieldFilter`/`terrainFieldFormat` follow the [runtime contract](/docs/core/runtime). `getCameraOrigin` is an optional local residency camera override. A mounted binding converts the scene camera to terrain-local coordinates by default.

Render-prop materials keep their React identity when node resources change. Do not add a key based on a position node ID. User callback identity changes may rebuild shaders; this is not an HMR/no-recompilation guarantee.

Query policy changes recreate the runtime; data configuration changes transact on the existing controller. Changed props update only their corresponding settings, so an unchanged elevation prop does not undo an imperative accepted edit. `cameraHysteresis` optionally suppresses small residency-camera movements; accepted edits still run while stationary.
