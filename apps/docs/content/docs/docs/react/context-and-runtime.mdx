---
title: Context and runtime
description: Share terrain state and query a coherent revision
---

`Terrain` provides its handle to descendants. Use `TerrainProvider` to share the same handle with siblings; it does not create another runtime.

```tsx
const terrain = useTerrainContext();
useFrame(() => {
  const sample = terrain.binding?.sampleWorld(player.position);
  if (sample?.status === "available") {
    player.position.fromArray(sample.position);
  }
});
```

Check each sample's availability. A render revision does not mean CPU data is fresh or resident at a requested location. `terrain.status.queryRevision` identifies CPU freshness. An edit receipt can be passed to `terrain.controller.requestSnapshot({minEditVersion: edit})`.

For a physics step, acquire a binding snapshot lease, query it, then release it. The lease pins both CPU data and placement. Local runtime leases use `math` Vec3 tuples and Float64 batch positions. User controls that assume global Y still require a flat/upright gameplay model even though the binding supports affine transforms.
