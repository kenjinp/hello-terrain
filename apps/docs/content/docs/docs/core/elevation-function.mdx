An `ElevationCallback` returns a scalar TSL node. Pass it as `elevation` to `createTerrain`, `useTerrain`, or `Terrain`, with a conservative range before scale.

```ts
import { createTerrain, type ElevationCallback } from "@hello-terrain/three";
import { sin } from "three/tsl";

const elevation: ElevationCallback = ({ worldPosition }) =>
  sin(worldPosition.x.mul(0.1)).add(sin(worldPosition.z.mul(0.1))).mul(0.5);

const terrain = createTerrain({
  renderer,
  elevation,
  elevationRange: { min: -1, max: 1 },
  elevationScale: 10,
});
```

This source produces displacement in `[-1,1]`; its scaled displacement is `[-10,10]` terrain units. Flat terrain displaces along local +Y; curved terrain follows its datum direction. Zero is valid data.

Use TSL operations for shader values, not JavaScript `Math.*`. Compose ordinary TSL functions, noise, and textures. The runtime evaluates the source over resident tile grids and produces elevation, bounds, normals, and rendering data.

## Coordinates

`worldPosition` is the undisplaced absolute datum position within the terrain coordinate system, before the binding's scene transform. It retains shader float32 limits. Render anchoring does not improve the precision of an arbitrary expression over this input.

`rootUV` is a projection-specific datum chart: face-local for a cube sphere and periodic for a torus. It is not a universal seamless global UV. `sourceFace` provides face selection when supplied by the evaluation context.

Fixed [regional source mappings](/docs/core/nodes/materials) use production `tileOriginVec2`, `tileLevel`, and `tileLocalUV` to form bounded coordinates. Supply the callback input object to the helper; do not reconstruct a large global coordinate first. These inputs are unavailable in some direct source-evaluation contexts, which the helper rejects.

The callback type also contains `rootSize`, `tileSize`, `tileUV`, and `nodeIndex` for backend evaluation. Tile slots are not persistent terrain identities. Making elevation depend on changing LOD or slot metadata changes the authored field and can introduce discontinuities.

## Sampling and source bounds

A compute callback has no implicit screen-space texture footprint. The installed Three backend uses level-zero texture sampling outside fragments unless a level is explicitly supplied. Filtering based on terrain LOD changes the sampled approximation and must be deliberate.

Declare finite `elevationRange` bounds for the complete callback, including combined layers. The declaration is not automatic range discovery or a clamp. It must remain valid when captured inputs change.

## Stationary edits

```ts
const edit = terrain.configure({
  elevation: nextElevation,
  elevationRange: { min: -2, max: 4 },
});
await terrain.requestSnapshot({ minEditVersion: edit });
```

After a view has been supplied, the snapshot request can schedule the required production without camera movement. Changing only a captured texture or uniform is not automatically observed; use ordered invalidation or [managed source edits](/docs/core/nodes/materials#managed-edits-when-needed).

Appearance-only textures can remain live material inputs. They do not need elevation invalidation or geometry readback.
