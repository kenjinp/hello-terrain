title: Topology
description: Choose terrain shape, dimensions, connectivity, and residency
---

A topology supplies root tiles, neighbor relationships, conservative bounds, and a matching [surface projection](/docs/core/projection). Pass it to `createTerrain` or `useTerrain`. Geometry dimensions have one authority: the topology.

| Factory                      | Required dimensions          | Domain                                       |
| ---------------------------- | ---------------------------- | -------------------------------------------- |
| `createFlatTopology`         | `rootSize`, `origin`         | One bounded XZ plane                         |
| `createInfiniteFlatTopology` | `rootSize`, `origin`         | Camera-centered grid of flat roots           |
| `createCubeSphereTopology`   | `radius`                     | Six cube-face charts projected onto a sphere |
| `createTorusTopology`        | `majorRadius`, `minorRadius` | Periodic ring and tube coordinates           |

Origins and centers use `{ x, y, z }` in the terrain coordinate system. Apply scene placement with the binding mesh or React primitive transform.

```ts
const topology = createCubeSphereTopology({ radius: 1000 });
const terrain = createTerrain({
  renderer,
  topology,
  elevation,
  elevationRange: { min: -1, max: 1 },
  elevationScale: 20,
});
```

Import the factories and `createTerrain` from `@hello-terrain/three`. In React, memoize a topology whose dimensions are unchanged; creating a new topology object is a configuration replacement.

## Flat domains

Flat topologies accept `origin`. Infinite flat topology also accepts `rootGridRadius`: the active root grid has `(2 * rootGridRadius + 1)²` roots around the camera. Source coordinates should remain stable as these roots move.

Infinite connectivity is not infinite residency. Queries outside resident tiles return unavailable. Adjacent tiles and mixed LOD still require correct geometry and sampling at their borders.

## Curved domains

Sphere and torus topologies accept `center` and `invert`. Inversion changes displacement/skirt orientation. Cube-face UVs need face selection when addressing an authored map.

The torus uses separate base resolutions along the ring and tube to avoid excessively stretched root tiles. The topology derives these from its dimensions. Applications use the same runtime query interface for every shape.

## LOD and bounds

Distance LOD is the default. Screen LOD uses the view's projection factor. The runtime supplies the declared scaled `elevationRange` to selection bounds, including before any readback. Bounds therefore do not require a CPU snapshot to be available.

`maxNodes` must accommodate topology roots and internal nodes. A maximum level alone does not guarantee a requested physical resolution.

Change dimensions by replacing the topology through `configure`; don't mutate accepted descriptors. Texture placement uses source mappings and is independent of render-tile layout.

For extension authors, `Topology` provides `rootTiles`, `neighborSameLevel`, `tileBounds`, `spaceCount`, `maxRootCount`, and `projection`. The exported types are the reference for complete signatures. See [projection](/docs/core/projection) and the [interactive examples](/examples).
