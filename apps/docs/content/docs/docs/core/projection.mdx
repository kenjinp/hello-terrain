---
title: Surface projection
description: Datum mapping and shape-specific terrain operations
---

A `SurfaceProjection` describes the datum, displacement direction, and shape-specific CPU/GPU operations. A [topology](/docs/core/topology) supplies connectivity and root selection. Built-in topology factories create their matching projection.

| Datum       | Displacement                          |
| ----------- | ------------------------------------- |
| Flat        | Along local +Y                        |
| Cube sphere | Radial to the sphere                  |
| Torus       | Along the tube's outward datum normal |

Inverted curved topologies reverse displacement orientation. All application queries use the common [terrain-local query interface](/docs/core/query/terrain-query).

## Extension contract

The exported `SurfaceProjection`, `SurfaceProjectionGpu`, and `SurfaceProjectionCpu` types define the backend hooks. `kind` identifies the projection for diagnostics; pipeline code dispatches through its hooks.

GPU hooks produce compute coordinates, render positions, and field normals. `createRenderPrecision` optionally supplies anchored rendering resources; built-in flat, sphere, and torus implementations preserve small offsets before float32 rounding.

CPU surface operations map a position to a datum key and reconstruct displaced positions and normals. CPU vector results use `Vec3` tuples from `math`. The Three backend connects these operations to its cache and runtime publication.

A custom shape must provide matching forward/inverse mapping, orientation, normal reconstruction, conservative bounds, and neighbor behavior. Compare GPU local geometry against a CPU double-precision reference. Cross-face continuity, mixed-LOD borders, and shadow behavior need validation; implementing a projection hook alone does not guarantee them.

## Coordinates and materials

Datum geometry and texture projection are different concerns. Use [material source mappings](/docs/core/nodes/materials) to place authored maps. A normalized chart coordinate is not an unlimited-precision position.

Rendering can use small anchor-relative offsets while source coordinates retain their stable meaning. Normals should use local derivatives or differences rather than subtraction of independently rounded large positions. See the [precision scope](/docs/core/runtime#precision-scope) for the tested limits.
