## Terrain material context

Ordinary TSL remains the material API. After first publication, `terrain.getRender().materialContext` supplies vertex-produced values interpolated into fragment shaders. React supplies the same context to the `<Terrain>` child function. Its identity stays stable across compatible resource updates.

| Input                    | Space and meaning                                                           |
| ------------------------ | --------------------------------------------------------------------------- |
| `elevation`              | Scaled local displacement **before skirt extrusion**; no radial subtraction |
| `datumNormalLocal`       | Undisplaced local datum normal                                              |
| `baseNormalLocal`        | Computed geometric terrain normal, before material detail                   |
| `slopeCosine`            | Cosine between normalized base and datum normals                            |
| `datumPositionLocal`     | Absolute local datum position, subject to shader f32 limits                 |
| `sourceUV`, `sourceFace` | Datum chart coordinates and face selection                                  |

Start with elevation and slope, then add paint without changing the terrain configuration:

```ts
import { createSourceMapping, terrainWeights, terrainDetailNormal } from "@hello-terrain/three";
import { mix, texture, vec3 } from "three/tsl";

const render = terrain.getRender();
if (!render) throw new Error("Wait for terrain publication before wiring the material");
const context = render.materialContext;
const snow = context.elevation.smoothstep(1800, 2400);
const rock = context.slopeCosine.oneMinus().smoothstep(0.1, 0.4);
material.colorNode = mix(vec3(0.15, 0.3, 0.08), vec3(0.4), rock).mix(vec3(1), snow);

// A shared texture can have different placement on each binding.
const mapping = createSourceMapping({ offset: [0, 0], scale: [0.5, 1] });
const mapUV = mapping.uv(context.sourceUV);
const paint = texture(weightMap, mapUV); // ordinary fragment derivative filtering
const [grassWeight, rockWeight] = terrainWeights([paint.r, paint.g]);
const painted = vec3(0.15, 0.3, 0.08).mul(grassWeight).add(vec3(0.4).mul(rockWeight));
material.colorNode = mix(painted, vec3(1), snow.max(rock));
material.normalNode = terrainDetailNormal(context, texture(detailNormalMap, mapUV).rgb, mapUV);
material.needsUpdate = true;
```

Apply `mapping.appliesTo(context.sourceFace)` when selecting a face chart. Mapping does not mutate `Texture.offset` or `repeat`. `terrainDetailNormal` builds a fragment cotangent frame from the actual mapping UV and view-position derivatives, then combines tangent detail with the terrain base normal. Pass encoded `[0,1]` normals; the returned node belongs in `normalNode` (view space). A normal texture's sampling UV alone does not change Three's default tangent frame.

Weight normalization is optional and supports any number of channels with a zero-weight fallback index. Categorical biome IDs need categorical sampling/decoding; independent wetness or density masks must not be normalized into a weight sum. RGBA specifies storage, not channel semantics. These appearance samples are not baked at mesh density or automatically read back to CPU.

## Managed edits when needed

Raw textures and uniforms remain live inputs outside snapshot guarantees. Use managed sources when an editor needs dependency invalidation, ordered edits, or safe replacement retirement:

```ts
import { createManagedTerrainTexture, bindTerrainSource } from "@hello-terrain/three";

const paint = createManagedTerrainTexture(weightMap); // texture remains borrowed
const detach = bindTerrainSource(terrain, paint, ["appearance"]);
material.colorNode = paint.sample(mapUV).rgb;

const receipt = await paint.edit(texture => {
  texture.image.data.set(newPixels); // synchronous mutation inside the reserved boundary
  texture.needsUpdate = true;
});
await receipt.retired;

const replacement = await paint.replace(nextCompatibleTexture);
await replacement.retired;
weightMap.dispose(); // safe now; managed sources never dispose borrowed textures

detach();
paint.releaseSamplers();
```

An appearance-only edit advances presentation state with no elevation, bounds, geometric-normal compute, or geometry readback. If a map also drives elevation, declare `['elevation', 'appearance']` and sample in compute with `paint.sample(uv, 'compute')` (explicit mip zero). After editing, target `terrain.getStatus().acceptedEditVersion` with `requestSnapshot({minEditVersion})`. Multiple declarations on one terrain share an edit boundary. Compatible replacement preserves material and sampler identity; format/type/color-space changes require a new source and shader mapping. Recompilation can still occur. Do not mutate borrowed pixels outside managed boundaries and expect version metadata to freeze them.

`createRegionalSourceMapping({face, level, x, y})` defines an optional fixed chart independent of the camera and render LOD. Its `uv(input)` subtracts integer tile origins before adding local fractions. It requires production tile-local coordinates; unavailable source-evaluation stages reject it explicitly. Select the face separately. Authors must define overlapping region seams, phase alignment, and fallback; this is not a streaming or virtual-texture engine. Global normalized f32 coordinates still have finite bits.

## Additional normal helpers

These exported helpers compose with ordinary TSL:

| Helper                                     | Input and result                                                              |
| ------------------------------------------ | ----------------------------------------------------------------------------- |
| `textureSpaceToVectorSpace(value)`         | Remaps `[0,1]` to `[-1,1]`                                                    |
| `vectorSpaceToTextureSpace(value)`         | Remaps `[-1,1]` to `[0,1]`                                                    |
| `blendAngleCorrectedNormals(base, detail)` | Normalized reoriented blend of two normals in `[-1,1]`                        |
| `deriveNormalZ(xy)`                        | Returns `(x, y, sqrt(max(0, 1-x²-y²)))`; remap encoded texture channels first |

For terrain materials, pass encoded RGB detail to `terrainDetailNormal` to construct the correct view-space normal from your mapping. Raw tangent-space normals cannot be assigned directly to a view-space `normalNode`.

See the [compressed texture example](/examples/materials/materials-bcn).
