---
title: Configuration
description: Configure terrain geometry, elevation, quality, and CPU snapshots
---

Pass initial settings to `createTerrain`. Update configurable settings with `terrain.configure(patch)`; it validates the candidate and returns an accepted edit version. Publication follows on `update`, or a snapshot request after the first view has been supplied.

## Terrain settings

| Setting              | Default                                     | Meaning                                                                      |
| -------------------- | ------------------------------------------- | ---------------------------------------------------------------------------- |
| `topology`           | Flat, size 256, origin zero                 | Geometry, dimensions, datum, and connectivity                                |
| `elevation`          | Constant zero                               | Ordinary TSL elevation callback                                              |
| `elevationRange`     | `{ min: 0, max: 0 }`                        | Conservative callback bounds before scale; set these for nonzero elevation   |
| `elevationScale`     | `1`                                         | Multiplier applied once to source displacement                               |
| `innerTileSegments`  | `61`                                        | Positive integer subdivisions of each inner tile                             |
| `maxNodes`           | `1024`                                      | Quadtree/storage capacity, including internal nodes; required roots must fit |
| `maxLevel`           | `16`                                        | Integer refinement limit, from 0 through 24                                  |
| `skirtScale`         | `100`                                       | Skirt extrusion in terrain units                                             |
| `terrainFieldFilter` | `"linear"`                                  | `"linear"` or `"nearest"` field sampling                                     |
| `terrainFieldFormat` | `"rgba16float"`                             | Normalized elevation/normal storage; `"rgba32float"` is also available       |
| `lod`                | `{ mode: "distance", distanceFactor: 1.5 }` | Distance refinement, or `{ mode: "screen", targetPixels: 8 }`                |

Screen LOD uses the projection factor supplied by `binding.viewFromCamera(camera, viewportHeight)`. Capacity and refinement limits are not accuracy guarantees.

The topology supplies its dimensions and datum center/origin in terrain-local coordinates. Scene placement belongs to `binding.mesh`. Supply a replacement topology to change its dimensions; do not separately configure a GPU radius.

## Creation-only options

`renderer` is an initialized, borrowed WebGPU renderer. `queries` controls CPU snapshots:

| Option                 | Default       | Meaning                                                   |
| ---------------------- | ------------- | --------------------------------------------------------- |
| `readback`             | `"on-change"` | Automatic snapshots, `"manual"` requests, or `"disabled"` |
| `maxRetainedSnapshots` | `3`           | Retention admission limit for pinned snapshots            |

These options are passed when creating the runtime, not through `configure`. Changing query policy in React recreates its runtime.

## Edits

```ts
const edit = terrain.configure({
  elevation: nextElevation,
  elevationRange: { min: -1, max: 1 },
  elevationScale: 50,
});
await terrain.requestSnapshot({ minEditVersion: edit });
```

Nested settings such as `lod` and `elevationRange` are complete replacement values. Equivalent settings do not invalidate production. A callback identity change can rebuild its shader.

Use `invalidateElevation()` for explicitly ordered mutations of captured source inputs. Use `invalidateAppearance()` for live material changes that do not affect geometry. [Managed source bindings](/docs/core/nodes/materials#managed-edits-when-needed) declare dependencies when an input serves both purposes.

In React, [useTerrain](/docs/react/use-terrain) accepts these settings plus flat-topology and camera conveniences. Applications configure the controller; they do not run terrain tasks.
