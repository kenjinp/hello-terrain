---
title: Raycasting
description: Intersect the sampled terrain surface with explicit incomplete results
---

Use `terrain.query.raycast(origin, direction, options)` in terrain-local coordinates, or `binding.raycastWorld(origin, direction, options)` in scene coordinates. Origin and direction are `math` Vec3 tuples; provide a finite unit direction.

```ts
const result = terrain.query.raycast([0, 100, 0], [0, -1, 0], {
  near: 0,
  far: 200,
  tolerance: 0.001,
  maxSteps: 256,
});
if (result.status === "hit") {
  console.log(result.sample.position, result.distance);
} else {
  console.log(result.reason);
}
```

| Option      | Default | Meaning                                     |
| ----------- | ------- | ------------------------------------------- |
| `near`      | `0`     | Nonnegative start distance                  |
| `far`       | `10000` | Finite end distance, greater than near      |
| `tolerance` | `0.001` | Positive intersection tolerance             |
| `maxSteps`  | `256`   | Integer work budget of at least two samples |

The current result is `hit` or `incomplete`; it does not return an authoritative miss. Incomplete reasons are `not-ready`, `outside-coverage`, and `work-budget`. Missing data or an exhausted search is not evidence that the ray misses the terrain.

The search samples and brackets the reconstructed surface. It is not an exact rendered-triangle intersection and may return incomplete for thin features or insufficient coverage. A successful result includes the snapshot revision through `result.sample.revision`.

## Three and React picking

A terrain binding installs a Three raycast bridge on its mesh. R3F pointer events and `Raycaster.intersectObject(binding.mesh)` use that bridge. It respects finite near/far limits; an infinite Three far limit is bounded to 10,000 scene units by the bridge.

Only successful terrain hits are added to the Three intersection list. An empty list cannot distinguish an incomplete terrain search from a miss; use `raycastWorld` when that distinction matters.

World queries apply scene placement and report world-space hit positions and distances. Local snapshot leases also expose `raycast`, allowing several tests against the same CPU revision.

See [terrain queries](/docs/core/query/terrain-query) for coverage, freshness, and lease lifetime.
