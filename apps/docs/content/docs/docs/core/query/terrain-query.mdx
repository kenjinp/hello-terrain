---
title: Terrain queries
description: Sample coherent terrain-local or scene-space CPU snapshots
---

Use `terrain.query` for terrain-local coordinates and `binding.sampleWorld` for scene coordinates. Both read a published CPU snapshot without evaluating the GPU source synchronously.

```ts
const result = terrain.query.sample([x, y, z]);
if (result.status === "available") {
  const { position, normal, elevation, revision, sampleSpacing, tile } = result;
}
```

Positions and normals are owned `Vec3` number tuples from `math`. Elevation is signed displacement along the datum direction after `elevationScale`, in terrain-local units. It is not generally world Y. Input points are projected onto the datum; this is not a globally nearest-surface search.

## Availability and freshness

A result is either `available` or `unavailable`. Unavailable reasons are `not-ready`, `disabled`, `outside-coverage`, `ambiguous-projection`, `stale`, or `disposed`. Zero elevation is valid data.

```ts
const edit = terrain.invalidateElevation();
await terrain.requestSnapshot({ minEditVersion: edit });
const current = terrain.query.sample([x, y, z], { minEditVersion: edit });
```

Provide a view through `update` before waiting for first production. Snapshot requests target the accepted edit or newer, not a retained historical version. Errors and disabled readback reject requests; failed transfers preserve the previous successful snapshot.

Coverage follows resident terrain tiles. Infinite terrain is not an infinite CPU collision cache. Check each result even when `getStatus().queryAvailability` is `"available"`.

## Scene placement

```ts
const sample = binding.sampleWorld(player.position);
if (sample.status === "available") player.position.fromArray(sample.position);
```

The binding applies its mesh transform and inverse-transpose normal transform. Reported elevation remains in local units under nonuniform scene scale. Singular transforms throw.

## Batches and leases

```ts
const lease = terrain.query.acquireSnapshot();
if (lease) {
  try {
    const results = lease.sampleBatch(new Float64Array([
      0, 20, 0,
      10, 20, 10,
    ]));
    // results.valid marks available entries.
    // positions, normals, elevations, and revision belong to this lease.
  } finally {
    lease.release();
  }
}
```

A lease pins one CPU record through later updates and runtime disposal. Calls after release throw; repeated release is harmless. `binding.acquireSnapshot()` additionally pins placement and exposes `sampleWorld(Vec3)` and `release()`.

`sampleSpacing` describes nominal source-grid spacing, not a maximum error. CPU reconstruction uses raw f32 elevation while rendering can use normalized f16 storage and a different normal approximation. See [snapshot architecture](/docs/core/query/how-it-works) and [raycasting](/docs/core/query/raycasting).
