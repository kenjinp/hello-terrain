title: Installation
description: Set up the WebGPU terrain runtime for Three.js or React

These guides describe the APIs in this repository checkout. Use matching builds of the terrain packages; a previously published package may not contain the checkout's runtime exports.

## Requirements

Use a WebGPU-capable browser and an initialized `WebGPURenderer` from `three/webgpu`. The repository currently validates against Three 0.182.0 and React Three Fiber 9. Ordinary WebGL materials are not the terrain runtime's rendering path.

## Three.js

```bash
pnpm add @hello-terrain/three three
pnpm add -D @types/three
```

The package includes its own declarations. TypeScript applications also need the matching Three declarations.

```ts
import { createTerrain, createTerrainBinding } from "@hello-terrain/three";

const terrain = createTerrain({ renderer }); // initialized WebGPURenderer
const binding = createTerrainBinding(terrain);
scene.add(binding.mesh);
await terrain.update(binding.viewFromCamera(camera, viewportHeight));
```

The default source is zero elevation. The binding creates a node material if none is supplied. Follow the [runtime guide](/docs/core/runtime) for frame updates, configuration, queries, and asynchronous disposal.

## React Three Fiber

```bash
pnpm add @hello-terrain/react @hello-terrain/three @react-three/fiber three react react-dom
pnpm add -D @types/three @types/react @types/react-dom
```

Create the WebGPU renderer in the Canvas `gl` callback and await `renderer.init()`. Render a node material using the terrain's `positionNode`. The complete setup is in [React getting started](/docs/react/getting-started).

If your application directly imports `Vec3` or operations from `math`, declare the same pinned dependency used by this checkout:

```bash
pnpm add math@1.0.0-canary-37519dcd-20260903
```

CPU positions use number tuples and Float64 batches; adopting this package does not change TSL shader precision.
