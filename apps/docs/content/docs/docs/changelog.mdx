Release notes for [`@hello-terrain/three`](https://www.npmjs.com/package/@hello-terrain/three) and [`@hello-terrain/react`](https://www.npmjs.com/package/@hello-terrain/react). These two ship together, so they share a version.

## Unreleased

This cycle separates **what renders** from **what stays resident**: tiles outside the view frustum stop rendering and recomputing, while residency anchors keep the terrain under characters and physics alive even when the camera looks away. GPU tile slots persist across frames so only dirty work is recomputed. Per-frame inputs are split into focused params with equality gating, and heightmap sampling is now precision-safe on every GPU vendor.

### Frustum + horizon culling — render only visible tiles

`computeTileVisibility` classifies every leaf each update — `Visible`, `Guard` (margin around the frustum), `FrustumCulled`, `HorizonCulled`, or `Unculled` (kept because horizon culling wasn't applicable) — and only the visible leaf set is drawn and dispatched. The resident set (`residentLeafSetTask`) and the visible set (`visibleLeafSetTask`) are now distinct: culling decides rendering, never data lifetime. Per-update telemetry (`TileVisibilityTelemetry`) reports candidate/visible/culled counts and the visible ratio.

### Residency anchors — terrain that outlives the frustum

`computeTileResidency` keeps tiles resident for two reasons: they are visible, or they intersect a **residency anchor** — a world-space sphere published via the `residencyAnchors` param (e.g. around the player). Anchored tiles keep ground queries, shadows, and character controllers working when the camera turns away, without rendering them. See the [Residency Anchors](/examples/residency-anchors) example.

### Persistent tile slots + incremental GPU compute

GPU tile slots are now a persistent cache (`createTileSlotCacheState` / `updateTileSlotCache`) instead of being rebuilt from scratch every update:

- Slots are **reused** across frames when a tile stays resident; only newly resident tiles allocate, and eviction is deferred until capacity demands it.
- Compute runs only for **dirty resident slots**; re-render uploads only **dirty visible slots** (indirect dispatch via `dirtyVisibleSlotBufferTask` / `dirtyVisibleSlotStorageTask`).
- A **content epoch** (`terrainFieldContentEpochTask`) invalidates all slots when anything that changes generated field values changes — elevation function, topology, root size/origin, radius, segment count, or elevation scale.
- `TileSlotTelemetry` reports reuse/allocation/eviction counts and dirty ratios per update.

Design rationale lives in `packages/three/spec/incremental-gpu-updates.md`.

### Split runtime params

The monolithic `quadtreeUpdate` param is replaced by:

- `cameraView` — camera origin + view-projection matrix (hysteresis via param `equals`)
- `residencyAnchors` — world-space support regions for off-screen residency
- `lodCriteria` — static LOD configuration

Vanilla and React consumers follow the same loop, with `terrainTargets({ compute, readback, gpuSpatialIndex })` selecting which pipeline stages a run executes:

```ts
graph.set(cameraView, readCameraView(camera, scratch));
graph.set(residencyAnchors, anchors);
await graph.run({ targets: terrainTargets({ ...pipeline }), resources: { renderer } });
```

### Precision-safe heightmap sampling

New `createHeightmapField` API: `r32float` storage read with `textureLoad` and
interpolated in fp32 (exact bilinear + Catmull-Rom bicubic, TSL and CPU
mirrors). Replaces the RG-packed helpers, whose decode-after-filter sampling
terraced on GPUs that quantize filtered unorm8 results (Apple silicon). See
`packages/three/spec/heightmap-precision.md` for the invariant and rationale.

```ts
const field = createHeightmapField({ data, width, height, minMeters, maxMeters });
const elevation: ElevationCallback = ({ rootUV }) => field.sampleMetersBicubic(rootUV);
```

### Incremental pipeline correctness

Fixes for tile flashing, permanent holes, and phantom ground in the persistent-slot pipeline:

- **Dirty work survives preempted runs.** The compute obligation is now a per-slot dirty bit cleared only after a dispatch actually ran, instead of an epoch stamped at enqueue time — a run aborted between the cache update and the compute dispatch used to drop the work forever, leaving permanently uncomputed tiles (holes). Re-queues are visible as `requeuedDirtyCount`.
- **LRU slot eviction.** Eviction now frees the least-recently-resident slot instead of the lowest index, keeping the substitution cache (just-split parents / just-merged children) warm under memory pressure.
- **Pending tiles are omitted, never drawn.** A visible tile whose compute hasn't landed and has no cached substitute is dropped from the draw list for that update (`notReadyVisibleCount`) instead of drawing uninitialized or leftover field data. New readiness telemetry: `visibleReadyCount`, `fallbackVisibleCount`, `notReadyVisibleCount`.
- **Queries are ready-gated.** The resident spatial index (CPU queries, raycasts, and the GPU spatial index) only resolves slots whose compute has run. Freshly allocated slots report `valid: false` instead of another tile's leftover elevations — previously a teleport could report phantom ground and drop characters through the terrain.

### GPU diagnostics

- **`createGpuProfiler`** — per-frame GPU-timeline timings split into render vs compute (`GpuFrameTimings`), with per-dispatch compute pass breakdowns, so "compute-bound or render-bound?" has a measured answer.
- **`disposeStorageBufferAttribute`** — destroys the GPU buffer behind a replaced storage attribute and detaches it from the renderer's backend cache; three has no `BufferAttribute.dispose()`, so replaced attributes previously leaked until renderer disposal.

### `@hello-terrain/work`

- **`param(initial, { equals })`** — optional equality comparator gates version bumps and dirty propagation in `graph.set()`.
- **`graph.run()` preemption** — overlapping runs coalesce when inputs are unchanged; in-flight runs abort when inputs change.

### `@hello-terrain/react`

- **`TerrainOptions` regrouped** — `culling`, `residency`, `lod`, and `pipeline` replace flat `camera`, `getCameraOrigin`, `cameraHysteresis`, `getResidencyAnchors`, `residencyHysteresis`, `runCompute`, `runReadback`, and `runGpuSpatialIndex`.
- **Thinner runner** — hysteresis, abort, and preemption live in `work`/`three`; React only sets params and calls `run()`.

### Docs

- New [Frustum Culling](/examples/frustum-culling) examples (flat, cube-sphere, torus) with an orbiting viewer and an animated helper camera driving visibility.
- New [Residency Anchors](/examples/residency-anchors) example.
- Agent GPU lab page for offline/headless GPU testing of the compute pipeline.

### Breaking ⚠️

- **`decodeUint16RG` and `sampleHeightmapMeters` removed.** Their decode-after-filter sampling is precision-unsafe. Use `createHeightmapField` instead.
- **`quadtreeUpdate` param removed.** Use `cameraView`, `residencyAnchors`, and `lodCriteria` instead.
- **React flat options removed.** Migrate to grouped options (see [Params](/docs/core/params)).
- **`writeUpdateParamsFromCamera` is internal wiring.** Prefer `readCameraView(camera, scratch)` for the `cameraView` param.

## 0.0.0-alpha.14 — Jupiter Stable Orbit

Heightmap and high-relief terrain should no longer show visible **stairstepping** in geometry and slope shadows, especially visible near ridges. 
The terrain field uses half-float storage (`rgba16float`), but elevation is now stored **per-tile normalized** so float16 precision tracks local relief instead of absolute meters at mountain scale.
This means each tile consumes the entire range/bit depth of f16, so each tile will be variably precise per relief. Near / Higher LOD tiles will have more precision, normally, as the area size is smaller and therefore elevation delta is minimized.

### Per-tile normalized terrain field

Each tile's `.r` channel stores elevation in `[0, 1]` relative to that tile's pack bounds (`packMin` / `packMax`), then denormalizes at sample time before `elevationScale` is applied. At ~3000 m of local relief this cuts float16 quantization error from ~2 m down to ~0.2 m; on typical 50–200 m tiles the error drops to sub-centimeter scale.

The compute pipeline now runs **elevation → bounds reduction → terrain-field pack**, so pack bounds are available before the field is written. Tile bounds storage grows from two to four floats per tile:

- `[0]` / `[1]` — LOD min/max (inner vertices only; unchanged semantics for readback and subdivision)
- `[2]` / `[3]` — pack min/max (all vertices, including skirts)

Render and GPU sampler paths bilinearly filter the terrain field for both elevation and normals.

### Heightmap TSL helpers

New exports for RG-packed 16-bit PNG heightmaps:

```ts
import { decodeUint16RG, sampleHeightmapMeters } from "@hello-terrain/three";

const elevation: ElevationCallback = ({ rootUV }) =>
  sampleHeightmapMeters(heightmap, rootUV, float(minM), float(maxM), float(rangeM));
```
### Under the hood

- New TSL helpers: `packNormalizedTerrainFieldSample`, `denormalizeTerrainFieldElevation`, `loadTilePackBounds`
- `midPipelineExecute` hook on compute pipelines for bounds reduction between upstream stages and terrain-field pack
- CPU readback consumers updated for the 4-float tile-bounds stride (LOD fields remain at offsets 0/1)
- **`@hello-terrain/react`:** `TerrainProps` is now a discriminated union — when you pass a `terrain` handle from `useTerrain()`, TypeScript no longer incorrectly requires `rootSize`, `origin`, `maxLevel`, and the other construction options on `<Terrain>`.

## 0.0.0-alpha.13 — Freezing Venus

LOD now subdivides against the **real terrain relief** instead of a flat datum. This fixes a regression from the last release.

### Surface-relative subdivision

Each tile's LOD bounding sphere is now built from its elevation:

- **Skirts are excluded** from the per-tile elevation range, so the bounds track the visible surface rather than the downward skirt geometry.
- **Flat topologies** measure vertical extent from the tile's own min/max displacement instead of a datum-relative height, fixing tiles that split too eagerly far from the camera.
- Remove camera "surface offset" hack, so that elevation is accounted for in the bounds, fixing a double-count.

### Fixes 🐛

- **Inverted cube-sphere picking.** Raycasts and surface queries on an `invert: true` cube-sphere now land on the correct side of the planet with correctly oriented (inward) normals. Previously hits were mirrored to the opposite face.
- **Stale picks after geometry changes.** Changing a curved surface's geometry at runtime (cube-sphere `radius`/`center`, torus `majorRadius`/`minorRadius`, `invert`) now rebuilds the CPU surface math, so markers and raycasts use the new geometry instead of the old radius.
- **Offset tile splitting** on flat and infinite-flat topologies, caused by the datum-relative bounds radius described above.

### Breaking ⚠️

- **`Topology.radius` / `Topology.center` removed.** These were duplicated on the topology; read them from `topology.projection.radius` / `topology.projection.center` instead.
- **`UpdateParams` LOD fields restructured** into a `LodCriteria` discriminated union. `mode: "screen"` now requires both `projectionFactor` and `targetPixels`; `mode: "distance"` (the default) takes an optional `distanceFactor`. The standalone `hysteresis` and `elevationAtCameraXZ` fields were removed.
- **`tileElevationRange` callback signature** changed from `(space, level, x, y, out)` to `(tile: TileId, out)`.
- **`SurfaceProjectionCpu.cameraSurfaceOffset` removed** along with the camera offset mechanism.

## 0.0.0-alpha.12 — Consensus Control

Terrain can now wrap a **torus**. Let's mainstream more fantastical world shapes! LOD and terrain querying are supported just as for planes and spheres. 

### Spinning up a donut

```tsx
import { Terrain, useTerrain } from "@hello-terrain/react";
import { createTorusTopology } from "@hello-terrain/three";
import { useMemo } from "react";

function Donut({ elevation }) {
  const topology = useMemo(
    () => createTorusTopology({ majorRadius: 1000, minorRadius: 360 }),
    [],
  );

  const terrain = useTerrain({
    topology,
    maxLevel: 16,
    elevationScale: 40,
    elevation,
  });

  return (
    <Terrain terrain={terrain} frustumCulled={false}>
      {({ positionNode }) => (
        <meshStandardNodeMaterial positionNode={positionNode} />
      )}
    </Terrain>
  );
}
```

See it running on the [torus example page](/examples/torus).

### Querying a closed surface

The torus doesn't have a tidy lat/long, so it uses the generic **surface query**: give it a world point in vec3 and it projects onto the surface for you.

```ts
// `probe` is a THREE.Vector3 somewhere near the surface
const query = terrain.runtime.surfaceQuery;
const sample = query.sampleTerrainByPosition(probe);

if (sample.valid) {
  marker.position.copy(sample.position);
  marker.quaternion.setFromUnitVectors(up, sample.normal);
}

// Pointer/raycast picking works identically across every topology
const hit = terrain.runtime.raycast.pick(event.ray);
```

### Turn it inside out 

Sphere and torus projections now take an **`invert`** flag. Flip it and elevation displaces _inward_ while skirts point _outward_.

```ts
createCubeSphereTopology({ radius: 1000, invert: true });
createTorusTopology({ majorRadius: 1000, minorRadius: 360, invert: true });
```

### What's New

- **`createTorusTopology(...)`**: a closed donut world with full render, LOD, query, and raycast parity.
- **Projection dependency injection**: topologies carry a `SurfaceProjection` strategy instead of using internal switching. New `projection/` module exports `createFlatProjection`, `createCubeSphereProjection`, and `createTorusProjection` (plus `CubeSphereProjectionConfig` / `TorusProjectionConfig`) for examples.
- **`invert` option** on the sphere and torus projection/topology configs.
- **Elevation-aware subdivision** via a new tile elevation "pyramid" from n-1 frame readback, so LOD reacts to elevation height better.
- New [torus example](/examples/torus).
- GPU objects are now **labeled for the WebGPU Inspector** to make profiling easier.

### Fixes 🐛

- **Continuous normals at cube-sphere seams.** The terrain field now stores true world-space normals `[height, Nx, Ny, Nz]` (computed from neighbor world positions), so shading no longer breaks across cube-face seams and tile edges.
- **GPU readback buffer leak fixed.** Three's `getArrayBufferAsync` was leaking a `_readback` buffer every frame; it's been replaced with a reused, properly destroyed staging buffer. This reduces hitching. 

## 0.0.0-alpha.11 — No Cuts Appropriate

You can now wrap terrain onto a **cube-sphere** and build planets, with seam-stitched LOD all the way down to the surface.

This release also introduces a new **[Terrain Query API](/docs/core/query/terrain-query)** for asking the terrain questions on the CPU, and renames the old "surface" concept to **"topology"** everywhere for consistency.

### Building a planet

```tsx
import { Terrain, useTerrain } from "@hello-terrain/react";
import { createCubeSphereTopology } from "@hello-terrain/three";
import { useMemo } from "react";

function Planet({ elevation }) {
  const topology = useMemo(
    () => createCubeSphereTopology({ radius: 1000 }),
    [],
  );

  const terrain = useTerrain({
    topology,
    radius: 1000,
    maxLevel: 16,
    elevationScale: 60,
    elevation,
  });

  return (
    <Terrain terrain={terrain} frustumCulled={false}>
      {({ positionNode }) => (
        <meshStandardNodeMaterial positionNode={positionNode} />
      )}
    </Terrain>
  );
}
```

There's a full runnable version on the [cube-sphere example page](/examples/cube-sphere).

### Asking the planet questions

Cube-sphere worlds get a **sphere query** keyed by latitude/longitude.

```ts
const query = terrain.runtime.sphereQuery;
const sample = query.sampleTerrainByLatLong(20, 40);

if (sample.valid) {
  marker.position.copy(sample.position);
  marker.quaternion.setFromUnitVectors(up, sample.normal);
}
```

[Raycasting](/docs/core/query/raycasting) now lives in its own path and works on every topology:

```ts
const hit = terrain.runtime.raycast.pick(ray);
// hit.position, hit.normal
```

### What's New

- **`createCubeSphereTopology(...)`** — six quadtree faces wrapped onto a sphere, with seam-stitching and curvature-aware LOD. Assign it through the [`topology` param](/docs/core/params).
- **[Terrain Query API](/docs/core/query/terrain-query)** — a consolidated CPU surface for elevation/position lookups, plus dedicated sphere queries for cube-sphere worlds.
- **[Raycasting](/docs/core/query/raycasting)** split into its own `terrain-raycast` path with a generic signed-distance march.
- **[Terrain Sampler](/docs/core/query/terrain-sampler)** unified into a single builder with cached results.
- New docs for topologies: [Topology](/docs/core/topology), Terrain Query, Raycasting, Terrain Sampler, and the cube-sphere example.
- `@hello-terrain/react` tracks above changes

### Under the hood

- **CPU/GPU terrain math deduped.** The 800+ line `cpu-terrain-cache.ts` was split into focused `terrain-snapshot`, `tile-lookup`, and `elevation-field-sampling` modules, with shared field/sphere math co-located in `gpu/tile.ts` behind CPU↔TSL parity tests.
- **`nodes/` folded into `tsl/`.** and other small re-arranging.
- Added a `typecheck` script and fixed the docs type-check.

### Breaking ⚠️

- **`surface` → `topology`.** The concept formerly called "surface" is now "topology" across the API, types, and docs. Update `surface` references and any deep imports from `quadtree/surface/*` (now `quadtree/topology/*`).
- **Dead exports removed** during the `nodes/` → `tsl/` consolidation, including `createTileRender`, `readElevationFieldVertex`, `sampleTerrainFieldNormal`, and the public `Texture3DBackend`.
